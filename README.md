## DriverPass Project Reflection

The DriverPass project was for a client that wanted a system to help students prepare for their driving tests. The system needed to support online classes, practice tests, and scheduling for on-the-road training. It also needed tools for employees to manage customers, reservations, reports, user accounts, and updates from the DMV.

I think I did a good job taking the information from the client interview and turning it into specific system requirements. I also think the different UML diagrams helped show the system from several viewpoints instead of trying to explain everything in one diagram.

If I could revise one part of the project, I would probably improve some of the UML diagrams. A few of them could be cleaner and more consistent with UML notation. I would spend more time simplifying the relationships and making the diagrams easier to read without adding unnecessary detail.

I interpreted the user's needs by going back to the interview and identifying what each type of user needed to be able to do. I then used those requirements when creating the system design and diagrams. Considering the user's needs is important because a system can work perfectly from a technical standpoint and still fail if it does not actually solve the customer's problem.

When designing software, I like to start by understanding the problem and breaking it into smaller pieces. From there, I identify the users, requirements, data, and main processes before deciding how the system should be structured. In the future, I would continue using requirements gathering, process models, object models, and UML diagrams to help organize a system before development begins.
